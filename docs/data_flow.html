Semantic Map 데이터 흐름

offline_semantic_mapping 의 모든 모듈(초록)과 데이터(그 외)를 하나의 의존 그래프로 그렸습니다. 위에서 아래로 흐르고, 화살표는 "이 데이터를 저 모듈이 읽는다" 또는 "저 모듈이 이 데이터를 만든다"입니다. 한 데이터가 여러 모듈로 다시 들어가면 주황 배지에 몇 곳인지 적혀 있습니다. 노드에 마우스를 올리면 그 노드에 닿는 선만 남습니다.

그림에서 보이는 재사용 지점

  • graph/ 는 세 번 쓰입니다. S 가 스캔을 최종 프레임으로 옮길 때, A 가 카메라 프레임 자세를 보간할 때, C 가 "키프레임 시각" 목록을 고를 때. 자세 하나를 모든 레이어가 공유하므로 지도 안에서 기하가 어긋나지 않습니다.
  • lidar_scans/ 는 세 번 쓰입니다. C 의 기하 점(키프레임 스캔), F 의 레이캐스팅, F3d 의 3D 사전맵. 같은 점군을 해상도와 목적만 바꿔 세 레이어로 만듭니다.
  • session_voxsem.npz 는 출력이면서 네 모듈의 입력입니다. F·F3d 는 동적 복셀 제거와 클래스 부여에, E 는 객체 아래 지형을 보는 데, G 는 패키지에 넣는 데 씁니다.
  • dataset/ 은 네 모듈이 읽습니다. D(객체 검출)뿐 아니라 C(카메라 자세·depth 가림 판정), V(영상)도 같은 프레임 파일을 씁니다.
  • map_manifest.json 은 끝이 아니라 허브입니다. 코스트맵·시각화·소비자·포털이 전부 이것만 읽고, 코스트맵은 만들어진 뒤 다시 매니페스트에 등록됩니다(왼쪽으로 되돌아가는 점선).
  • GPU 가 필요한 모듈은 B, D 와 옵션 E(VLM) 뿐입니다. 나머지는 CPU 기하 계산이라 산출물이 있으면 건너뛰고 재개할 수 있습니다.
